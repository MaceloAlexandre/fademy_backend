<objective>
Add a backend endpoint `GET /api/users/suggestions` that returns "people you might want to follow" for the authenticated caller, scoped to their institution, excluding the caller, anyone they already follow (pending OR accepted), and any block relationship in either direction. Staff roles sort before alunos.

Purpose: Provides the single data source consumed by both the SearchPage suggestions list and the FeedPage carousel (Plans 02 and 03).
Output: New `suggestUsers` controller, its route, and tests.
</objective>

Existing patterns to reuse exactly (do NOT reinvent):

From src/controllers/user.controller.js — searchUsers already builds the block-exclusion set and institution scoping:
```
const blocks = await Block.find({ $or: [{ blockerId: viewerId }, { blockedId: viewerId }] }).lean();
const excludedIds = blocks.map((b) => b.blockerId.toString() === viewerId ? b.blockedId : b.blockerId);
excludedIds.push(viewerId);
// query: User.find({ institutionId, _id: { $nin: excludedIds } }).select('name avatarUrl role isPrivate').lean()
```
The select shape `'name avatarUrl role isPrivate'` is the exact field set the frontend card needs (it reads user._id, user.name, user.avatarUrl, user.role, user.isPrivate). Mongoose returns _id by default — keep it.

From src/controllers/post.controller.js getFeed — the Math.min safe-limit pattern (feed caps at 50). For suggestions use Math.min(Number(req.query.limit) || 15, 20).

From src/models/Follow.js — Follow docs have { followerId, followingId, status } where status is 'pending' | 'accepted'.
From src/models/User.js — role enum: ['admin', 'coordenador', 'professor', 'funcionario', 'aluno'].
