# Quick Task 260610-dv1: Fix desktop full-width fixed-position elements

## Task

On desktop, the app simulates a mobile viewport via `AppShell.module.css` `.shell { max-width: 480px; margin: 0 auto }`. Fixed-position elements that need to stay inside that 480px column use the pattern:

```css
left: 50%;
transform: translateX(-50%);
width: 100%;
max-width: 480px;
```

(see `.header` / `.bottomNav` in `src/components/AppShell/AppShell.module.css`).

4 fixed-position rules instead used `left: 0; right: 0;`, spanning the full desktop viewport while the rest of the page stays in the 480px column.

## Task 1: Apply the 480px-column pattern to the 4 affected rules

**Repo:** `MINIREDESOCIAL_FRONT` (sibling repo at `/home/maceloalexandre/Documentos/projetos/MINIREDESOCIAL_FRONT`)

**Files:**
1. `src/pages/PostDetailPage/PostDetailPage.module.css` — `.submitErrorWrap`
2. `src/pages/PostDetailPage/PostDetailPage.module.css` — `.inputBar`
3. `src/components/ChatComposer/ChatComposer.module.css` — `.inputBar`
4. `src/pages/ConversationThreadPage/ConversationThreadPage.module.css` — `.submitErrorWrap`

**Action:** In each rule, replace `left: 0; right: 0;` with `left: 50%; transform: translateX(-50%); width: 100%; max-width: 480px;`. No other properties change.

**Verify:** All 4 rules now use the 480px-column pattern; no other CSS properties altered; CSS-only change (no JS edits).

**Done:** Comment input bar (PostDetailPage), its error banner, the chat composer input bar, and the chat thread error banner are all constrained to the 480px mobile-simulated column on desktop, matching AppShell header/bottomNav behavior.
