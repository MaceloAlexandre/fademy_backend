| `--space-sm` | 8px | Gap between message bubbles from the same sender, internal gaps in conversation list item |
| `--space-md` | 16px | ConversationListItem padding, page padding, bubble internal padding, gap between avatar and content |
| `--space-lg` | 24px | Empty state vertical rhythm, gap between message groups from different senders |

Exceptions:
- Touch target minimum: 44px (`--touch-min`) — chat header icon button, send button, image-attach button, conversation-list row tap area (whole row tappable, naturally exceeds 44px height)

- Message bubble max-width: 75% of thread column width (fixed proportion, not a spacing token — standard chat-bubble convention, prevents full-width bubbles on wide viewports)
- Message image thumbnail: 200px max-width within bubble, `border-radius: var(--radius-card)` minus 4px to nest inside bubble radius
- Fixed composer bar height: 56px (matches `PostDetailPage`'s `.inputBar` — direct visual precedent for "fixed bottom input bar above bottom nav")

## Color

All tokens already declared in `tokens.css`. No new tokens are added in this phase.

| Role | Value | CSS Variable | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | `#083C5D` dark blue | `--color-dominant` | App background, header, bottom nav, ConversationsListPage/ThreadPage background, **received-message bubble background** |
| Secondary (30%) | `#333333` charcoal | `--color-secondary` | Fixed composer bar background (matches `PostDetailPage` `.inputBar` precedent verbatim) |
| Surface/text | `#D6CFC1` beige | `--color-surface` | Bubble text, names, body copy on dark backgrounds, **sent-message bubble text** |
| Accent (10%) | `#8C6E4F` tobacco brown | `--color-accent` | Unread indicator dot, **sent-message bubble background**, send button (active state), chat header icon when unread conversations exist |
| Accent alt | `#E6E6FA` soft lavender | `--color-accent-alt` | Focus ring outline only — no fill or border use |
| Destructive | `#FD8080` coral | `--color-destructive` | Error banners only (no destructive *actions* exist in this phase's scope — see Copywriting) |

Accent (`#8C6E4F`) is reserved for, in this phase:
1. Unread indicator dot (8px circle) on conversation-list rows with unread messages — **identical visual treatment to `NotificationCard`'s unread dot** (same hex, same 8px size, same position convention)
2. Sent-message bubble background (`var(--color-accent)`, text `var(--color-surface)`) — the single highest-frequency accent surface in this phase; this is the "my messages" visual signal, mirroring the universal chat-app convention (sender's own bubbles in the brand/accent color, recipient's in a neutral surface)
3. Send button — filled accent button when composer has content to send (mirrors `btnPrimary`/`PrimaryButton` treatment), muted/disabled when empty
4. Chat header icon — switches from muted `rgba(214,207,193,0.5)` to `--color-accent` when any conversation has unread messages (mirrors the bell icon's exact unread-state convention, D-02 "mirrors the bell icon's placement/style exactly")

Accent is NOT used for: received-message bubbles (these use `--color-dominant` with a subtle border to stay visually distinct from the page background — see Component Inventory), conversation-list row backgrounds (no tint — unlike `NotificationCard`'s unread tint, because the unread *dot* alone is sufficient signal here and a full-row tint would compete visually with the bubble-color accent budget), timestamps, or "new message" / picker rows.

Sent vs. received bubble treatment (the core visual contract for the thread view):
- **Sent** (`message.senderId === currentUserId`): background `var(--color-accent)` (#8C6E4F), text `var(--color-surface)` (#D6CFC1), right-aligned
- **Received**: background `var(--color-dominant)` (#083C5D) with `border: 1px solid rgba(214, 207, 193, 0.15)` (same separator opacity as existing card borders, ensures the bubble reads as distinct from the page background which is the SAME dominant color), text `var(--color-surface)`, left-aligned

This keeps the 60/30/10 budget intact: dominant remains the dominant surface (received bubbles + page background are the same color, differentiated only by a hairline border — exactly like `PostCard`'s existing `border-bottom` separator convention), secondary appears only on the composer bar (matching its existing "elevated input surface" role from `PostDetailPage`), and accent stays reserved to the explicit four uses above — most visibly the sent-bubble color, which is the single most-repeated accent surface in the entire app once a conversation has more than a few messages. This is an intentional, larger allocation of accent than prior phases (which used it sparingly for CTAs/badges) — flagged here explicitly because chat bubbles are inherently accent-heavy in any chat UI; the alternative (sent bubbles in secondary/charcoal) would make "my messages" indistinguishable from the composer bar and violate the "accent = the user's own identity signal" convention this app already uses (e.g., active bottom-nav tab, unread indicators).

Destructive (`#FD8080`) is reserved for, in this phase:
1. `ErrorBanner` for fetch/send/upload errors only — there are no destructive user *actions* in this phase's scope (no delete-message, no delete-conversation, no block-from-chat — block already lives in Phase 3's profile UI and is out of scope here)

## Component Inventory

New components for this phase. All use CSS Modules co-located with the component file, following the established pattern. Reuse `ErrorBanner`, `Spinner`, `PrimaryButton` without modification.

### AppShell update (chat entry icon — connects D-02, D-03)

`AppShell.jsx` and `AppShell.module.css` are updated in this phase, mirroring the exact bell-icon wiring pattern from Phase 5.

**Changes:**
1. A new icon button is added to the header, positioned **immediately adjacent to the bell icon** (D-02 — "next to the notification bell"; exact left/right order is Claude's discretion — recommend chat icon to the LEFT of the bell, since chat is the newer/lower-frequency surface and notifications remain the primary glance-target, but either order satisfies D-02's "adjacent" requirement)
2. Icon: `MessageCircle` from `lucide-react` (already a project dependency — no new icon library), `size={24}`, `aria-hidden="true"`
3. Button class: a new `.chatBtn` in `AppShell.module.css` that is **visually and structurally identical to `.bellBtn`** — same `width: 44px; min-height: 44px`, same `color: rgba(214, 207, 193, 0.5)` muted default, same `:focus-visible` outline (D-02 "mirrors the bell icon's placement/style exactly" — this is a hard visual-parity requirement, not a loose guideline)
4. Icon color becomes conditional: `--color-accent` when any conversation has unread messages, otherwise the existing muted `rgba(214, 207, 193, 0.5)` — identical conditional-color pattern to the bell
5. A badge pill identical to `.badge` (same 20px pill, same position, same typography) renders the count of conversations-with-unread (not total unread messages — conversation count is the simpler, less noisy signal and matches "how many people are waiting on you" rather than "how many messages total")
6. `onClick={() => navigate('/chat')}`
7. Unread-conversation count is computed from the conversations-list fetch (or a lightweight dedicated count endpoint — **planner's call**; the contract only fixes the visual contract, not the data-fetching strategy). It does NOT reuse `useNotificationPolling` (that hook is scoped to `Notification` documents) — this is a separate concern even though `message_received` notifications exist; deriving the badge from live conversation/message state (via the socket connection that's already established for the chat feature) is more accurate and avoids a second polling loop running app-wide. **Recommendation: compute unread-conversation count from the same data the `ConversationsListPage` fetches, refreshed on `message:new` socket events — zero additional network surface.**

### ConversationsListPage

Route: `/chat` (new — wired into `App.jsx` routes, nested inside `AppShell`)

Layout:
- Page-level header row: no page title text (matches FeedPage/NotificationsPage convention), but DOES contain the "new message" / compose icon button (D-04), right-aligned within the content area top — `Plus` or `SquarePen` from `lucide-react`, `size={24}`, `44px` touch target, `aria-label="Nova mensagem"`, `onClick={() => navigate('/chat/new')}`
- Below that: full-width scrollable list of `ConversationListItem` rows — same list-container pattern as `FeedPage`/`NotificationsPage` (`display: flex; flex-direction: column`, no gaps, rows separated by `border-bottom`)
- Sort order: most-recently-active conversation first (`updatedAt: -1` per RESEARCH.md's recommended query) — simple reverse-chronological, no pinning/grouping (mirrors D-04 "simple reverse-chronological" precedent from Phase 5 notifications)
- No pull-to-refresh (the socket connection keeps the list current in real time — adding pull-to-refresh would be redundant, same simplicity reasoning as Phase 5's "polling already covers freshness")

States:
1. **Initial loading**: `Spinner` (28px) centered in page, `aria-label="Carregando conversas..."`
2. **List with conversations**: list of `ConversationListItem` rows
3. **Empty list**: empty state block (see Copywriting) — centered, `--space-2xl` vertical padding, heading (body/600) + body (body/400, muted), structurally identical to Phase 5's NotificationsPage empty state, but WITH a clear next-action reference ("Toque em Nova mensagem...") since there IS an obvious next step here (unlike notifications, which has none)
4. **Error**: `ErrorBanner` at top of list with retry guidance

### ConversationListItem

Single conversation row in the list (D-05's explicit layout: avatar + name + last-message preview + timestamp + unread indicator).

Layout (horizontal flex row, internal padding `--space-md`, gap `--space-md` — directly mirrors `NotificationCard.module.css` `.card` structure, the closest sibling per D-05's "full chat-app style" framing and the explicit code_context citation):

- **Avatar**: 40px circle, `--radius-avatar`, `object-fit: cover`, `alt={otherUser.name}` — the OTHER member of the 1:1 conversation (never the current user — derive by filtering `memberIds` against `req.user.id`)
- **Content block** (flex: 1, vertical stack, gap `--space-xs`, `min-width: 0` for text truncation):
  - **Name row**: body/16px, `--weight-semibold`, `--color-surface`, single line with `text-overflow: ellipsis; white-space: nowrap; overflow: hidden`
  - **Last-message preview**: label/14px, single line truncated (same overflow treatment). Read state: `rgba(214, 207, 193, 0.5)` muted (matches timestamp muted color). Unread state: `--color-surface` at `--weight-semibold` (full-strength + bold — this is the SECOND unread signal beyond the dot, mirrors how the bell icon doubles its unread signal via both badge AND icon-color in Phase 5's established convention). Image-only messages render "📷 Foto" per the Copywriting contract.
- **Trailing column** (flex column, align-items: flex-end, gap `--space-xs`, `flex-shrink: 0`):
  - **Timestamp**: label/14px/400, `rgba(214, 207, 193, 0.5)` muted — reuse `formatRelativeTime()` **verbatim** (the exact same helper duplicated in `PostCard.jsx`/`NotificationCard.jsx`/`PostDetailPage.jsx` — do not introduce a fourth copy with different formatting; if the planner wants to extract it to a shared util, that's a worthwhile cleanup, but the OUTPUT FORMAT must remain "agora"/"Xmin"/"Xh"/"Xd" identically)
  - **Unread indicator**: 8px circle, `background: var(--color-accent)` — **pixel-identical to `NotificationCard`'s `.unreadDot`** (same hex, same size, same `border-radius: 50%`). Positioned in the trailing column below the timestamp (NOT as a row-background tint — see Color section rationale for why this phase does not replicate the unread row-tint convention)

Row states:
- **Has unread messages**: bold/full-strength preview text + unread dot visible
- **No unread**: muted preview text, no dot (omit entirely — matches Phase 5's "prefer omit for simplicity" resolution, no `visibility: hidden` placeholder)

Row border: `border-bottom: 1px solid rgba(214, 207, 193, 0.1)` (identical separator to `PostCard`/`UserResultCard`/`NotificationCard`)
Tap target: entire row navigates to `/chat/:conversationId` — implemented as a focusable element with `role="button"`/`tabIndex={0}`/`onKeyDown` OR a `<Link>` wrapper (prefer `<Link>` — same "less code, accessible by default" reasoning Phase 5 already settled on)

### NewConversationPage (the "new message" picker — D-04)

Route: `/chat/new`

Layout:
- Page heading: "Nova mensagem" (heading/20px/600) — this page needs its own visual anchor since it's a modal-like flow stepping outside the list (a `Voltar`/back affordance via `ArrowLeft` from `lucide-react`, mirrors `ComposePage`'s back-arrow pattern, `aria-label="Voltar"`)
- Below: scrollable list of mutual-follower rows — **same row layout as `UserResultCard`'s avatar+name+role structure, MINUS the `FollowButton`** (RESEARCH.md Assumption A3, confirmed here as the contract: avatar 40px + name (body/600) + role label (label/14px, muted) — no follow/request control, since mutual-follow is the precondition for appearing in this list at all)
- Tapping a row: calls `POST /api/conversations` (find-or-create per RESEARCH.md Pattern 5), then navigates to `/chat/:conversationId` — show a brief inline `Spinner` (16px) on the tapped row during the in-flight request, disable other rows from being tapped simultaneously (prevents the double-tap race RESEARCH.md Pitfall 3 describes)

States:
1. **Loading**: `Spinner` (28px) centered, `aria-label="Carregando contatos..."`
2. **List with mutual followers**: rows as described above
3. **Empty** (no mutual followers): empty state — heading "Nenhum contato disponível" + body explaining the mutual-follow requirement (see Copywriting) — this is the ONE empty state in this phase's scope that benefits from a slightly longer explanatory body, because the underlying rule (mutual-follow gate) is not obvious to a first-time user and the empty state is the natural teaching moment
4. **Error**: `ErrorBanner` with retry guidance

### ConversationThreadPage

Route: `/chat/:conversationId`

Layout:
- Page header: the OTHER member's name (heading/20px/600, truncated) + back arrow (`ArrowLeft`, `aria-label="Voltar"`, navigates to `/chat`) — mirrors `PostDetailPage`'s header-with-back-arrow convention. Avatar optionally shown next to the name (small, 32px) — **Claude's discretion**, purely decorative, skip if it adds friction
- Scrollable message list: `MessageBubble` components, chronological top-to-bottom, auto-scrolled to bottom on load and on new-message arrival (standard chat convention)
- Message grouping: consecutive messages from the same sender within a short window render with reduced gap (`--space-sm` between, vs `--space-lg` between different-sender groups) — **standard chat visual grouping, Claude's discretion on the exact time-window threshold** (recommend simply grouping by consecutive `senderId` regardless of time gap — simplest possible rule, avoids a timestamp-diff calculation entirely, matches CLAUDE.md "Simplicity First")
- Fixed bottom composer (`ChatComposer`) — **directly mirrors `PostDetailPage`'s `.inputBar` pattern**: `position: fixed; bottom: 56px` (above bottom nav), `height: 56px`, `background: var(--color-secondary)`, `border-top: 1px solid rgba(214, 207, 193, 0.15)`

States:
1. **Initial loading**: `Spinner` (28px) centered, `aria-label="Carregando mensagens..."`
2. **Thread with messages**: bubbles as described
3. **Loading older messages** (scroll-to-top pagination, cursor-based per RESEARCH.md `messageSchema.index({ conversationId: 1, _id: -1 })`): `Spinner` (24px) centered above the oldest visible message — mirrors FeedPage's infinite-scroll spinner placement (inverted: "load more" is upward, not downward, in a chat thread)
4. **Empty thread** (brand-new conversation, zero messages yet): centered prompt — "Diga oi para **{Nome}**" (body/600) — a friendly, low-friction opener that names the concrete first action; NOT a generic "no messages" dead-end, since the user just deliberately opened this conversation and the obvious next step is "type something"
5. **Error (load)**: `ErrorBanner` at top, "Erro ao carregar mensagens. Tente novamente."
6. **Error (send)**: `ErrorBanner` directly above the composer (mirrors `PostDetailPage`'s `.submitErrorWrap` — `position: fixed; bottom: calc(56px + 56px)`), "Não foi possível enviar a mensagem. Tente novamente." — message text remains in the input for retry

### MessageBubble

Single message rendering — the core visual unit of the thread.

Layout:
- Container: flex row, `justify-content: flex-end` for sent / `flex-start` for received
- Bubble: `max-width: 75%`, `padding: var(--space-sm) var(--space-md)`, `border-radius: var(--radius-card)` (12px, matches existing card radius convention — no new radius token)
- Sent: `background: var(--color-accent)`, `color: var(--color-surface)`, aligned right
- Received: `background: var(--color-dominant)`, `border: 1px solid rgba(214, 207, 193, 0.15)`, `color: var(--color-surface)`, aligned left
- Text: body/16px/400, `white-space: pre-wrap; word-break: break-word` (matches `PostCard`'s text-rendering treatment — plain text, React's default escaping, NO `dangerouslySetInnerHTML`, per RESEARCH.md's XSS mitigation note)
- Image attachment (when `mediaUrls.length > 0`): rendered ABOVE the text (if any) inside the bubble, `max-width: 200px`, `border-radutos: calc(var(--radius-card) - 4px)`, `object-fit: cover`, `margin-bottom: var(--space-xs)` if text follows — tapping the image opens it full-screen (simple `<img>` in a fixed-position overlay with a close affordance — **Claude's discretion on the exact lightbox implementation**; the contract only requires that tapping a message image shows it larger, not that it's a sophisticated gallery)
- Timestamp: label/14px/400, `rgba(214, 207, 193, 0.5)` (sent) or same muted tone (received) — rendered BELOW the bubble, aligned to match the bubble's side, `margin-top: var(--space-xs)`. Reuse `formatRelativeTime()` verbatim.
- Optimistic send state (D-decision implied by RESEARCH.md "optimistic send UI"): a message the current user just sent renders immediately with `opacity: 0.6` until the REST POST resolves; on success, `opacity: 1`; on failure, the bubble shows a small inline retry affordance (`aria-label="Tentar enviar novamente"`) — **Claude's discretion on exact retry-affordance styling**, but it must be visually distinguishable from a successfully-sent bubble (e.g., a small `RotateCw` icon from `lucide-react` at the bubble's trailing edge)

### ChatComposer

Fixed bottom input bar — directly mirrors `PostDetailPage`'s `.inputBar` (same 56px height, same `--color-secondary` background, same `border-top`, same `:focus-within` outline treatment).

Layout (horizontal flex row, `align-items: center`, `gap: var(--space-xs)`, `padding: 0 var(--space-sm)`):
- **Image-attach button**: icon-only, `Camera` or `Image` from `lucide-react` (mirrors `PhotoUpload`'s `Camera` icon choice for visual-language consistency), `44px` touch target, muted `rgba(214, 207, 193, 0.5)` default / `--color-accent` when an image is staged, `aria-label="Anexar imagem"`. Same 5MB size guard + same allowed types (`image/jpeg,image/png,image/webp`) as `ComposePage`/`PhotoUpload` — **verbatim reuse of the constants and error copy**, do not redefine
- **Staged-image preview** (when an image is selected but not yet sent): small thumbnail (32px) inline in the bar with a remove affordance (`X` icon, mirrors `ComposePage`'s remove-image pattern), shown to the left of the text input
- **Text input**: `flex: 1`, `background: transparent; border: none; outline: none`, `color: var(--color-surface)`, body/16px, placeholder "Mensagem...", `aria-label="Mensagem"` — directly mirrors `.commentInput` from `PostDetailPage.module.css`
- **Send button**: icon-only, `Send` from `lucide-react`, `44px` touch target. Disabled (muted, `opacity: 0.5`, `cursor: not-allowed`) when both text is empty AND no image is staged; active (`color: var(--color-accent)`) when there's content to send. `aria-label="Enviar mensagem"`
- Submitting state: `Spinner` (16px) replaces the send icon, input + attach button disabled during the in-flight request — mirrors `NotificationCard`'s inline-action loading treatment

Send behavior (per RESEARCH.md Pattern 4 — REST is the durable write path):
1. Tap send → optimistic bubble appears immediately (see `MessageBubble` optimistic state)
2. `multipart/form-data` REST POST to `/api/conversations/:id/messages` (image upload + text together, mirrors `ComposePage`'s multipart submission)
3. On success: optimistic bubble's `opacity` returns to `1`, server-assigned `_id`/`createdAt` replace optimistic placeholders
4. On failure: optimistic bubble shows retry affordance, `ErrorBanner` appears above composer, input text is preserved (not cleared) for retry
5. Recipient receives the message via the `message:new` socket event — appended live to their open thread (if viewing it) or reflected in their conversation-list preview/unread-dot (if not)

## Interaction States

### Loading
- Page-level load (any of the three new pages): `Spinner` (28px) centered, page-specific `aria-label` (see Copywriting)
- Pagination/older-messages load: `Spinner` (24px) centered above oldest visible message
- Picker row tap (creating/opening conversation): `Spinner` (16px) inline on the tapped row, other rows disabled
- Composer submit: `Spinner` (16px) replaces send icon, input + attach disabled

### Error
- List/thread/picker load error: `ErrorBanner` at top, copy per element (see Copywriting) — structurally identical to Phase 5's list-load-error pattern
- Send error: `ErrorBanner` above composer (fixed position, mirrors `PostDetailPage`'s `.submitErrorWrap`), non-destructive (text preserved for retry)
- Mutual-follow / blocked gate violations: `ErrorBanner` with the specific copy strings defined above — these surface defensively (the picker already prevents reaching this state under normal use; this is for stale-link/edge-case coverage)

### Empty
- No conversations: centered empty state with actionable next-step copy ("Toque em Nova mensagem...") — **differs from Phase 5's no-CTA empty state** because this phase has an obvious, nameable next action (Phase 5's empty notifications state correctly had none)
- No mutual followers (picker): centered empty state explaining the mutual-follow rule in plain language — the one place in this phase where a slightly longer explanatory body is warranted, because the underlying rule isn't visible anywhere else in the chat UI
- Empty thread (brand-new conversation): friendly named-recipient prompt ("Diga oi para {Nome}"), NOT a generic empty-list message — this is a "first message" prompt, conceptually different from a true empty state

### Real-time / optimistic states
- Sent message (optimistic): `opacity: 0.6` until REST confirms, then `opacity: 1`
- Sent message (failed): retry affordance + `ErrorBanner`, text preserved
- Received message (live): appends to thread instantly via `message:new` socket event; if the thread isn't open, updates conversation-list preview + unread dot + chat-icon badge
- Connection state: no user-facing "reconnecting" UI (Claude's discretion, justified above) — Socket.io's automatic reconnection (per RESEARCH.md) handles this transparently; only persistent REST failures surface to the user

### Focus / Accessibility
- All interactive elements: `outline: 2px solid var(--color-accent-alt); outline-offset: 2px` on `:focus-visible` (unchanged convention, applies to chat icon, compose icon, conversation rows, picker rows, composer controls, send button)
- Buttons: `cursor: pointer`; disabled: `opacity: 0.5; cursor: not-allowed`
- Avatars: `alt={otherUser.name}` (never the current user's own avatar in list/thread contexts)
- Chat header icon: `aria-label="Mensagens"`
- Chat badge: visually `aria-hidden="true"` with adjacent `.sr-only` span (mirrors bell badge's `.sr-only` pattern verbatim, including the existing utility class in `AppShell.module.css`)
- Conversation row / picker row: `<Link>` wrapper preferred (accessible by default — same resolution Phase 5 settled on for `NotificationCard`, avoiding the `UserResultCard` keyboard-gap precedent)
- Message images: `alt="Imagem enviada por {senderName}"` (or "Imagem enviada por você" for sent messages)
- Composer text input: `aria-label="Mensagem"`
- Send button: `aria-label="Enviar mensagem"`, disabled state communicated via `disabled` attribute (not just visual styling)
- Image-attach button: `aria-label="Anexar imagem"`
