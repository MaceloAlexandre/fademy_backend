<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → GET /api/users/search?q= | Untrusted search query; regex metacharacters can cause ReDoS |
| Client → GET /api/users/:id | Viewer may attempt to read a profile from another institution or a blocked user |
| Client → PATCH /api/users/me | Only isPrivate should be updatable; attacker may try to inject other fields |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Denial of Service | searchUsers | mitigate | ReDoS: escape metacharacters with `q.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')` + slice to 100 chars before RegExp construction |
| T-03-07 | Information Disclosure | searchUsers | mitigate | Cross-tenant leak: institutionId scoped from req.user.institutionId (JWT) — never from query param |
| T-03-08 | Information Disclosure | getProfile | mitigate | Block check covers both directions ($or both blockerId and blockedId) before returning any profile data; blocked users see 404 |
| T-03-09 | Information Disclosure | getProfile | mitigate | Private profile returns only name/avatarUrl/role/followStatus for non-followers — bio, counters, posts not included in response |
| T-03-10 | Tampering | updateMe | mitigate | Only `isPrivate` field accepted; validated as boolean before update — no other User fields writable via this endpoint |
| T-03-11 | Tampering | npm/pip/cargo installs | accept | No new packages in this plan — all pre-existing, slopcheck [OK] |
