<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/media/presign | Unauthenticated (pre-account) request controlling contentType + size |
| browser → S3 (presigned PUT) | Direct upload bypassing the API; bounded by the signed request |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | presign content-type/size | mitigate | Validate against image allowlist + MAX_UPLOAD_BYTES at signing time before any S3 call (D-11) |
| T-02-07 | Denial of Service | unbounded upload size | mitigate | Reject size > MAX_UPLOAD_BYTES; short presign TTL (S3_PRESIGN_TTL default 300s) limits replay window |
| T-02-08 | Information Disclosure | AWS credentials | mitigate | Credentials read only via env.js; never returned to client; never logged; only the signed uploadUrl is exposed |
| T-02-08b | Tampering | client-supplied avatarUrl key | mitigate | Server generates the S3 key and returns it as a bare `key`; registration (Plan 03) echoes the server-issued key instead of reverse-parsing it from a client-controlled URL |
| T-02-SC | Tampering | npm installs (@aws-sdk/*) | mitigate | blocking-human verification checkpoint before install ([ASSUMED] — no RESEARCH audit) |
</threat_model>
