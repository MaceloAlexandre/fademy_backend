<objective>
Deliver the registration vertical slice that closes the backend entry loop: an invited person submits the registration form, the backend validates the invite (Plan 01), confirms the uploaded photo exists in S3 (Plan 02), creates the user scoped to the invite's institution and role, and consumes a slot. Also enables CORS so the React frontend (Plan 04) can reach the API.

Purpose: This is the join point of invites + S3 — without it, an invite cannot become an account.
Output: `registration.controller`, the public `POST /api/auth/register` route, CORS middleware in app.js, and an integration test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/auth/register | Unauthenticated; client supplies token, email, password, avatarUrl/avatarKey |
| registration → S3 | objectExists confirms the server-issued avatarKey actually points at an uploaded object |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Elevation | role/institution from client | mitigate | role and institutionId derived ONLY from the invite, never from req.body (D-12) |
| T-02-10 | Spoofing | fake avatarUrl | mitigate | objectExists(avatarKey) must return true before user creation (D-10/D-11); key is the server-issued value from presign, not parsed from the client URL (T-02-08b); reject otherwise |
| T-02-11 | Tampering | reuse of closed invite | mitigate | Reject status!=='active' / expired / usesCount>=maxUses; increment + close atomically after create (D-06) |
| T-02-12 | Information Disclosure | password handling | mitigate | bcrypt.hash with env.BCRYPT_ROUNDS; store passwordHash only; never log/return the hash or plaintext (Phase 1 pattern) |
| T-02-13 | Information Disclosure | duplicate-email enumeration | accept | 409 reveals email-in-use within institution — acceptable for invite-only registration UX (UI-SPEC copy "Este e-mail já está em uso") |
| T-02-SC | Tampering | npm install (cors) | mitigate | blocking-human verification checkpoint before install ([ASSUMED]) |
</threat_model>
