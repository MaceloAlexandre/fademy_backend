# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2: accept-invite, register (with mandatory
> profile photo), and login/logout. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property         | Value                                                                  |
|------------------|------------------------------------------------------------------------|
| Tool             | none — CSS custom properties + utility classes (see Styling Approach)  |
| Preset           | not applicable                                                         |
| Component library| none (hand-rolled primitives; shadcn deferred — no components.json)    |
| Icon library     | lucide-react (tree-shakeable, React-native API, MIT)                   |
| Font             | Inter (Google Fonts — system fallback: system-ui, sans-serif)          |

### Styling Approach (Claude's Discretion — locked here for executor)

Use **CSS custom properties** declared in `src/styles/tokens.css`, imported once at
the root. Component styles live in co-located `.module.css` files (CSS Modules via Vite's
built-in support — zero config, no extra deps). This keeps the bundle small and the token
contract explicit without pulling in a full design system for three screens.

No Tailwind, no styled-components, no emotion. The token file IS the design system for
Phase 2.

Source: Claude's Discretion (CONTEXT.md D-18 defers fine-grained UI to this spec)

Declared values (all multiples of 4):

| Token   | Value | CSS Variable         | Usage                                     |
|---------|-------|----------------------|-------------------------------------------|
| xs      | 4px   | `--space-xs`         | Icon gaps, badge padding, inline nudges   |
| sm      | 8px   | `--space-sm`         | Input-label gap, compact list rows        |
| md      | 16px  | `--space-md`         | Default form field spacing, card padding  |
| lg      | 24px  | `--space-lg`         | Section padding, gap between form groups  |
| xl      | 32px  | `--space-xl`         | Screen top/bottom safe-area padding       |
| 2xl     | 48px  | `--space-2xl`        | Logo-to-form gap on auth screens          |
| 3xl     | 64px  | `--space-3xl`        | Not used in Phase 2 (reserved later)      |

Exceptions:
- Touch targets (buttons, file-upload trigger): minimum **44px tall** regardless of scale,
  per WCAG 2.5.5 (mobile finger target).
- Photo upload preview area: **120px × 120px** fixed (circular crop, not a spacing token).

| Destructive     | `#FD8080` | `--color-destructive` | Destructive actions only (see Copywriting Contract)                |

**Accent (`#8C6E4F` marrom/caramelo) reserved for:**
1. Primary CTA button background (e.g., "Criar conta", "Entrar")
2. Active/filled state of the photo upload trigger button
3. Step-progress indicator fill (active step dot)

Accent is NOT used on: links, secondary buttons, form borders, hover states, icons.

**Contrast notes for executor:**
- Body text `#D6CFC1` on `#333333` card background: contrast ~5.1:1 — passes AA.
- Body text `#D6CFC1` on `#083C5D` page background: contrast ~4.7:1 — passes AA.
- CTA button: white (`#FFFFFF`) label on `#8C6E4F` accent background: contrast ~3.9:1 —
  acceptable for large button text (AA Large). If failing automated audit, use `#F5F0EB`
  (off-white) as label color instead; do NOT darken the accent.
- Destructive `#FD8080` on `#333333`: contrast ~4.0:1 — passes AA Large for error labels.
  Do not use `#FD8080` as body text on any background.

**Dark theme:** Phase 2 is dark-first (dominant = dark blue). No light theme this phase.

## Screen-by-Screen Interaction Contract

### Screen 1: Accept Invite (`/invite/:token`)

**Layout:** `AuthShell` (logo centered, card below). Single-column, max-width 400px,
centered horizontally, 24px side padding on mobile.

**States:**

| State         | What the user sees                                                                 |
|---------------|------------------------------------------------------------------------------------|
| Loading       | `Spinner` centered in card, "Verificando convite..." label below                   |
| Valid invite  | Role badge (`--color-accent` background, white text, e.g. "aluno"), institution name, slot info ("X vagas restantes"), `<PrimaryButton>` "Aceitar convite" |
| Invalid token | `<InviteStatus variant="error">` with copy from Copywriting Contract              |
| Expired       | `<InviteStatus variant="expired">` with copy from Copywriting Contract            |
| Revoked       | Same as expired (same user-facing message — do not distinguish revoked vs expired) |
| Full (0 slots)| `<InviteStatus variant="full">` with copy from Copywriting Contract               |

**Interaction:** "Aceitar convite" button → `GET /api/invites/:token` to pre-validate,
then navigate to `/register?token=:token`. Token stored in component state (not
localStorage) until register completes.

**No form on this screen.** It is read-only information + one CTA.

---

### Screen 2: Register (`/register?token=:token`)

**Layout:** `AuthShell`. Scrollable single-column form. Sticky "Criar conta" button
at the bottom (position: sticky, bottom: 0, full-width, 16px vertical padding).

**Field order (top to bottom):**

1. Photo upload (see Photo Upload sub-section)
2. Full name — text input, required, minLength 2
3. Email — email input, required, unique validation on submit
4. Password — password input, required, minLength 8, toggle visibility icon (lucide `Eye`/`EyeOff`)
5. Confirm password — password input, required, must match password

**No institution selector** — institution is derived from the invite token (D-08).
**No role selector** — role is fixed by the invite token.

**Photo Upload sub-section (AUTH-04, PLAT-03, D-10/D-11):**

The photo upload is a mandatory step. The executor MUST implement this flow:

1. **Upload trigger:** Circular placeholder (120×120px, dashed border `--color-accent`,
   `--color-secondary` background). Center-aligned. Lucide `Camera` icon (24px) inside.
   Label below: "Foto de perfil *" (asterisk in `--color-destructive`).
2. **File selection:** Clicking the trigger opens the native file picker (hidden
   `<input type="file" accept="image/jpeg,image/png,image/webp">`). Max file size: 5 MB.
3. **Preview:** On selection, show a circular thumbnail (120×120px, object-fit: cover)
   replacing the placeholder. "Trocar foto" link below (14px, `--color-surface`, underline).
4. **Upload to S3 (BEFORE submit):** On "Criar conta" click:
   a. Call backend `POST /api/media/presign` with `{ contentType, size }`.
   b. Show `Spinner` over the photo area + disable the submit button.
   c. Browser PUTs the file bytes directly to the presigned S3 URL (`axios.put(presignedUrl, file, { headers: { 'Content-Type': file.type } })`).
   d. On S3 PUT success: proceed with account creation `POST /api/auth/register` including `avatarUrl`.
   e. On S3 PUT failure: show `ErrorBanner` "Falha no upload da foto. Tente novamente." — do NOT proceed to registration.
5. **No S3 upload = no form submission.** The "Criar conta" button is disabled until a
   photo file is selected (not yet uploaded — upload triggers on form submit, not on selection).

**Validation timing:** Inline validation on field blur (not on every keystroke). Error
message appears below the field in `--color-destructive` at 14px/400.

**Submit button state machine:**

| State        | Label              | Enabled | Style                         |
|--------------|--------------------|---------|-------------------------------|
| Default      | "Criar conta"      | If photo selected | Accent bg, white text |
| No photo     | "Criar conta"      | Disabled | 50% opacity, cursor: not-allowed |
| Uploading    | "Enviando foto..." | Disabled | Spinner left of label         |
| Registering  | "Criando conta..." | Disabled | Spinner left of label         |
| Success      | — (redirect)       | —       | Navigate to `/login?registered=1` |

---

### Screen 3: Login (`/login`)

**Layout:** `AuthShell`. Logo prominent at top. Card with form. Max-width 400px.

**Fields:**
1. Email — email input, required
2. Password — password input, required, toggle visibility

**Below form:** "Não tem convite? Peça ao seu professor ou coordenador." — informational
text only, 14px/400, `--color-surface` at 70% opacity. No self-serve registration link.

**Success banner (one-time):** When arriving from `/login?registered=1`, show a brief
success banner: "Conta criada com sucesso! Faça login para continuar." (`--color-accent`
background, white text, auto-dismiss after 4 seconds or on first input focus).

**Submit button:**

| State      | Label       | Enabled  |
|------------|-------------|----------|
| Default    | "Entrar"    | Always   |
| Loading    | "Entrando..." | Disabled |
| Success    | — (redirect)| —        |

On success: store JWT in `localStorage` key `fademy_token`, navigate to `/`.

**Logout affordance:** Not a screen — a button rendered in the post-login shell header.
Clicking it clears `localStorage.removeItem('fademy_token')` and navigates to `/login`.
No confirmation dialog (stateless logout, D-13).

## Interaction Patterns

### Form validation
- Validate on blur (field loses focus), not on keystroke.
- On submit: re-validate all fields before firing any network request.
- Error messages: below the field, 14px/400, `--color-destructive`.
- Error border: `--color-destructive` 1px solid on the input element.
- No inline success icons on fields (keep it simple).

### Loading states
- Every async action (presign, S3 PUT, register, login, invite validation) disables the
  triggering button and shows `<Spinner>` (24px, `--color-surface` color) left of the
  button label or centered in the action area.
- No skeleton screens for Phase 2 (forms, not data lists).

### Error recovery
- API errors surface via `<ErrorBanner>` at the top of the card, above the first field.
- Field-level validation errors appear inline below the field.
- After an API error, the form is re-enabled immediately (not after delay).

### Accessibility
- All inputs have an associated `<label>` (htmlFor/id pair).
- `aria-required="true"` on required fields.
- `aria-invalid="true"` + `aria-describedby` pointing to the error message element when
  a field has an error.
- `<PrimaryButton>` uses `type="submit"` inside a `<form>` — native form submission.
- Focus ring: 2px solid `--color-accent-alt` (`#E6E6FA`), 2px offset — visible on dark bg.
- Color is never the sole indicator of state (icon + text accompany all status colors).
