<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/posts (multipart) | User-supplied text, files, linkUrl, categoryIds |
| comment API response → DOM | Comment text + author name rendered into the thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04D-01 | Elevation of Privilege | aluno link compose | mitigate | Client surfaces the backend 403 as a clear error; the authoritative role gate lives server-side (Plan 01) — client never grants the capability |
| T-04D-02 | Tampering (XSS) | comment + post text render | mitigate | Render all comment/post fields as React text children; no dangerouslySetInnerHTML |
| T-04D-03 | Denial of Service | oversized image upload | mitigate | Client-side 5MB-per-file check mirrors backend MAX_UPLOAD_BYTES; backend remains the authoritative limit |
| T-04D-04 | Tampering | category id injection | mitigate | Only ids from the fetched /api/categories list are selectable; backend stores them as ObjectIds (invalid ids rejected by Mongoose cast) |
| T-04D-SC | Tampering | npm installs | mitigate | No new frontend packages. Any install requires blocking human verify per package legitimacy gate |
</threat_model>
