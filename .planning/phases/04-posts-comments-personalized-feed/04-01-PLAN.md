<objective>
Build the complete backend slice for posts and the personalized feed: the Post model, an S3 upload extension for post images, a controller that creates posts (with role-gated links, multi-image S3 upload, category tagging), serves a cursor-paginated personalized feed (accepted follows minus blocked users in both directions), serves a single post, and exposes the seeded categories the composer needs.

Purpose: This is the backend half of the core loop — without it, no post can be created or read and the feed cannot exist. It is a self-contained vertical slice: a real HTTP client could create a post and fetch a feed after this plan completes.

Output: Post model, extended s3.service, post.controller + tests, category.controller, post.routes, category.routes, and app.js mounts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /api/posts | Untrusted multipart body (text, linkUrl, categoryIds, image files) crosses here |
| client → GET /api/posts/feed | Untrusted cursor/limit query params; cross-tenant read attempts |
| server → S3 | Files uploaded to bucket; content-type and size are attacker-influenced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | createPost linkUrl (CONT-03) | mitigate | Controller rejects aluno role with non-empty linkUrl -> 403 before persisting; hasLink derived server-side, never trusted from client |
| T-04-02 | Information Disclosure | getFeed / getPost cross-tenant | mitigate | Every query filters by req.user.institutionId sourced from verified JWT; getPost 404s on institution mismatch |
| T-04-03 | Information Disclosure | getFeed block bypass (FEED-02) | mitigate | Exclude authors blocked in EITHER direction via $nin blockedIds spanning blockerId and blockedId |
| T-04-04 | Denial of Service | image upload abuse | mitigate | multer limits.fileSize = MAX_UPLOAD_BYTES (5MB) and array cap of 4; mimetype allowlist (jpeg/png/webp) rejects others with 400 |
| T-04-05 | Spoofing | authorId / institutionId tampering | mitigate | authorId and institutionId taken only from req.user (verified JWT), never from request body |
| T-04-06 | Tampering | unbounded cursor/limit | mitigate | limit capped via Math.min(..., 50); cursor used only in `_id < cursor` comparison (no injection surface in Mongoose) |
| T-04-SC | Tampering | npm installs | mitigate | No new npm packages introduced in this plan (multer, mongoose, aws-sdk already present); if any install is needed, halt for blocking human verify per package legitimacy gate |
</threat_model>
