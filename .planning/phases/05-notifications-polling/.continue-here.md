## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Verify-before-merge | Asked user to manually re-test a bug fix while the fix commit was still sitting unmerged on a worktree branch — user tested stale `main` code repeatedly, reporting false "still broken" results | blocking | Always run the worktree merge/cleanup step BEFORE issuing any verification request to the user; confirm the fix commit is an ancestor of `main` (`git merge-base --is-ancestor <hash> main`) before asking for re-test, and explicitly instruct the user to restart dev servers |
| Sibling-repo path confusion | Frontend paths like `MINIREDESOCIAL_FRONT/src/hooks/...` look like they live inside this repo but actually resolve one directory up, in a wholly separate git repo with its own remote and history | blocking | Brief any frontend-touching executor with absolute paths and `git -C <abs-path-to-MINIREDESOCIAL_FRONT>` for every git operation; explicitly state it is exempt from the `worktree-agent-*` branch guard |
| Quota-exceeded with uncommitted partial work | A spawned executor hit its session quota mid-task, returned no commits/no SUMMARY.md, but had left correct, useful uncommitted changes in the working tree | advisory | When resuming after a quota failure, spawn a FRESH executor (not SendMessage resume — the old session is gone) with a `<resume_context>` block describing the existing uncommitted state, and instruct it to evaluate (not blindly discard or blindly trust) before continuing |
