|----------|-------------|
| browser → PATCH /api/follows/:id/accept|reject | Client sends a follow id (notification.refId); server (Phase 3) enforces that only the followee can accept/reject |
| browser → PATCH /api/notifications/:id/read | Client marks its own notification read; server enforces ownership (plan 05-01) |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-05A-01 | Elevation/IDOR | accept/reject call | mitigate | refId comes from the user's own JWT-scoped notification list; the Phase 3 accept/reject controller independently 403-guards that the caller is the request target — no new authority granted client-side |
| T-05A-02 | Tampering/IDOR | mark-read after action | mitigate | Marks only `notification._id` from the rendered list; server ownership guard (T-05-02) applies |
| T-05A-03 | Cross-site Scripting | actor name in aria-label/labels | mitigate | React escapes interpolated text; aria-label is an attribute string, not HTML; no dangerouslySetInnerHTML |
| T-05A-04 | Tampering | npm installs | accept | No new packages added; legitimacy gate not triggered |
