<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → GET /api/notifications | Authenticated user requests a list; must receive only their own rows |
| client → PATCH /api/notifications/:id/read | Authenticated user supplies an arbitrary :id; must be blocked from mutating others' rows |
| anonymous → POST /api/auth/register | Untrusted registrant triggers an invite_received notification to a real existing user (invite creator) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | listNotifications | mitigate | Query scoped strictly by `userId: req.user.id` (from verified JWT, never request input); test (c)/(b) assert cross-user isolation |
| T-05-02 | Elevation/IDOR | markRead `/:id/read` | mitigate | Load by id then `notification.userId.toString() !== req.user.id` → 403 before any write; test asserts non-owner 403 |
| T-05-03 | Spoofing | invite_received recipient | mitigate | Recipient = `invite.invitedById` read from the persisted Invite doc, not from request body; actorId = server-created `user._id` |
| T-05-04 | Denial of Service | listNotifications limit param | mitigate | `Math.min(limit, 50)` caps page size; cursor pagination avoids large skips |
| T-05-05 | Tampering | npm/pip/cargo installs | accept | No new packages installed this plan (uses existing models/service/mongoose); package legitimacy gate not triggered |
</threat_model>
