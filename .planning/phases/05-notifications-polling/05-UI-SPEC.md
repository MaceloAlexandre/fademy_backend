## Spacing Scale

All tokens already declared in `MINIREDESOCIAL_FRONT/src/styles/tokens.css`. Reference by CSS variable; do not redeclare.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--space-xs` | 4px | Gap between unread dot and content, inline gaps in action buttons |
| `--space-sm` | 8px | Gap between Aceitar/Rejeitar buttons, internal gaps in NotificationCard |
| `--space-md` | 16px | NotificationCard padding, page padding, gap between avatar and text block |
| `--space-lg` | 24px | Empty state vertical rhythm |

- Unread indicator dot: 8px diameter (fixed, not a spacing token)
- Badge on bell icon: 20px height pill, min-width 20px (fixed, not a spacing token; sized to fit `--text-label` at 14px without overriding the type scale)
- Bell icon button: 44px × 44px (unchanged from Phase 4 — already in `AppShell.module.css` `.bellBtn`)

## Typography

All tokens already declared in `tokens.css`. Reuse without modification — no new sizes/weights introduced.

| Role | Size | Weight | Line Height | CSS Variable |
|------|------|--------|-------------|--------------|
| Body | 16px | 400 regular | 1.5 | `--text-body` / `--weight-regular` / `--lh-body` |
| Label | 14px | 400 regular | 1.4 | `--text-label` / `--weight-regular` / `--lh-label` |
| Heading | 20px | 600 semibold | 1.2 | `--text-heading` / `--weight-semibold` / `--lh-heading` |
| Display | 28px | 600 semibold | 1.1 | `--text-display` / `--weight-semibold` / `--lh-display` |

Usage in this phase:
- Display (28px/600): not used
- Heading (20px/600): NotificationsPage title is provided by `AppShell` wordmark/header pattern — no separate page heading needed (matches FeedPage, which has none); empty-state heading uses **body/600**, not heading scale (consistent with Phase 4 feed empty state)
- Body (16px/400): notification action text ("[Nome] começou a seguir você", etc.), empty state body copy
- Label (14px/400): timestamp (muted), badge number (semibold override — see below), Aceitar/Rejeitar button labels, status labels ("Aceito"/"Rejeitado")

Note: badge number on the bell icon uses label size (14px) at **600 semibold** (not 400) for legibility at small pill size — this is the only weight deviation, matching the existing precedent of `--weight-semibold` being used selectively on labels (e.g. `UserResultCard` `.name`).

## Color

All tokens already declared in `tokens.css`. No new tokens are added in this phase.

| Role | Value | CSS Variable | Usage |
|------|-------|-------------|-------|
| Dominant (60%) | `#083C5D` dark blue | `--color-dominant` | App background, header, bottom nav, NotificationsPage background |
| Secondary (30%) | `#333333` charcoal | `--color-secondary` | Unread notification card background tint base (applied as overlay — see below) |
| Surface/text | `#D6CFC1` beige | `--color-surface` | Action text, names, body copy on dark backgrounds |
| Accent (10%) | `#8C6E4F` tobacco brown | `--color-accent` | Unread indicator dot, badge background, "Aceitar" button, active bell icon state |
| Accent alt | `#E6E6FA` soft lavender | `--color-accent-alt` | Focus ring outline only — no fill or border use |
| Destructive | `#FD8080` coral | `--color-destructive` | "Rejeitar" button border/text, error banner |

Accent (`#8C6E4F`) is reserved for, in this phase:
1. Unread indicator dot (8px circle) on unread notification cards
2. Badge pill background on the bell icon (unread count)
3. "Aceitar" inline action button (background, per D-05)
4. Bell icon color when notifications are unread (icon itself switches from muted `rgba(214,207,193,0.5)` to `--color-accent` — gives a second unread signal beyond the badge)

Accent is NOT used for: read notification cards, status labels ("Aceito"/"Rejeitado" use muted surface color), timestamps, "Rejeitar" button (uses destructive), or hover states on non-CTA elements.

Unread card background treatment: `rgba(140, 110, 79, 0.08)` — accent at 8% opacity overlay on the dominant background (NOT a flat secondary-color fill; keeps it subtle per D-03 "fundo destacado" while staying within the 60/30/10 budget — this is a tint, not a new surface color).

Destructive (`#FD8080`) is reserved for, in this phase:
1. "Rejeitar" inline action button border + text (ghost style, matches `btnConfirmDestructive` pattern from `FollowButton`)
2. `ErrorBanner` for fetch/mark-read errors

| Error state (accept/reject action) | "Algo deu errado. Tente novamente." | Matches existing `FollowButton`/`BlockButton` error copy verbatim — reuse, don't invent new wording |
| Bell icon aria label | "Notificações" | Already set in `AppShell.jsx` (Phase 4) — unchanged |
| Bell icon badge aria label | "{count} notificações não lidas" (or "mais de 9 notificações não lidas" when capped) | Screen-reader-only text accompanying the visual badge pill |
| Loading state | (no text — `Spinner` only, `aria-label="Carregando notificações..."`) | Matches FeedPage initial-load pattern |
| Page title | (none — no in-page heading; `AppShell` header wordmark suffices) | Matches FeedPage (no page-level heading) |

Destructive actions in this phase: **none requiring confirmation dialogs**. "Rejeitar" a follow request is a one-tap inline action (per D-05/D-06 — no confirmation step; matches the lightweight nature of the action and the explicit "card updates in-place" decision). This deliberately diverges from the `FollowButton`/`BlockButton` confirm-then-destroy pattern because rejecting a follow request is reversible (the requester can simply request again) and low-stakes — adding a confirmation step here would contradict D-06's "in-place update, no friction" intent. Mark-as-read has no confirmation (implicit, low-stakes, reversible by design — notifications don't "unread").

## Component Inventory

New components for this phase. All use CSS Modules co-located with the component file, following the established pattern. Reuse `ErrorBanner`, `Spinner`, `PrimaryButton` without modification. Reuse `FollowButton`'s confirm-action CSS class names as a styling reference for Aceitar/Rejeitar buttons (do not import `FollowButton` itself — these are different actions on a different model).

### AppShell update (connects D-09, D-10 — bell icon wiring)

`AppShell.jsx` and `AppShell.module.css` are updated in this phase. The bell button markup already exists (Phase 4 D-11) — this phase makes it functional.

**Changes:**
1. `onClick={() => {}}` → `onClick={() => navigate('/notifications')}`
2. Bell icon color becomes conditional: `--color-accent` when `unreadCount > 0`, otherwise the existing muted `rgba(214, 207, 193, 0.5)`
3. A badge pill is rendered absolutely positioned at the top-right corner of the bell button when `unreadCount > 0`:
   - Background: `--color-accent`
   - Text: `--color-surface`, `--text-label` (14px) at `--weight-semibold`, `line-height: 1` (no font-size override — the pill is sized to the existing 14px label token, not the other way around)
   - Shape: pill, `border-radius: 10px`, `min-width: 20px`, `height: 20px`, `padding: 0 4px` (20px sized to comfortably contain 14px text at line-height 1 plus padding, while staying visually compact against the 44px bell button)
   - Position: `position: absolute; top: 4px; right: 4px`
   - Display value: the raw count for 1–9, `"9+"` for any value ≥ 10 (cap threshold — Claude's discretion per 05-CONTEXT, chosen because it's the single-digit-to-pill-width breakpoint and matches the suggested example in CONTEXT specifics)
4. Polling hook (`useNotificationPolling` or equivalent) is mounted at the `AppShell` level (per D-09) — it owns `unreadCount` state and passes it down to the bell badge. Implementation detail (custom hook with `setInterval`, 5000ms per D-08, cleared on unmount) is **Claude's discretion** at planning/build time; the contract only fixes: (a) interval = 5000ms, (b) mount point = `AppShell`, (c) it must not block initial page render (fire-and-forget background fetch), (d) it must pause/resume correctly on tab visibility changes is NOT required for MVP (no visibility API integration needed — keep it simple per CLAUDE.md "Simplicity First").

### NotificationsPage

Route: `/notifications` (new — wired into `App.jsx` routes, nested inside `AppShell`)

Layout:
- Full-width scrollable list of `NotificationCard` components — same list-container pattern as `FeedPage` (`display: flex; flex-direction: column`, no gaps, cards separated by `border-bottom`)
- No pagination UI complexity beyond what FeedPage already established: simple cursor-based "load more on scroll" OR simple offset pagination — **paging strategy is Claude's discretion** per 05-CONTEXT (mirrors FEED-03 cursor pattern OR simpler `?page=`/`?skip=` — pick whichever is less code given `Notification` has no existing pagination helper; do not over-engineer for a list that will typically be short)
- No pull-to-refresh in this phase (the 5-second poll already keeps the list current — adding pull-to-refresh would be redundant complexity; this is a deliberate simplicity call, not an oversight)

States:
1. **Initial loading**: `Spinner` (28px) centered in page, `aria-label="Carregando notificações..."`
2. **List with notifications**: list of `NotificationCard` rows, most recent first (D-04 — simple reverse-chronological, no date grouping)
3. **Fetching more (if paginated and scrolled to bottom)**: `Spinner` (24px) centered below last card — matches FeedPage infinite-scroll pattern
4. **Empty list**: empty state block (see Copywriting) — centered, `--space-2xl` vertical padding, matches Phase 4 feed empty-state structure (heading + body, no CTA needed here since there's no obvious next action like "search people")
5. **Error**: `ErrorBanner` at top of list with retry guidance

### NotificationCard

Single notification row in the list. Tap anywhere (except inline action buttons) navigates to the related content AND marks the notification read (D-02).

Layout (horizontal flex row, internal padding `--space-md`, gap `--space-md` — directly mirrors `UserResultCard.module.css` `.card` structure since D-01 explicitly calls for visual consistency with established card patterns):

- **Avatar**: 40px circle, `--radius-avatar`, `object-fit: cover`, `alt={actor.name}` — actor is the user who triggered the event (e.g., the new follower, the commenter)
- **Content block** (flex: 1, vertical stack, gap `--space-xs`):
  - **Action text row**: body/16px/400, `--color-surface`. Actor name rendered inline at `--weight-semibold`, remaining text at `--weight-regular` (e.g., "**Maria Silva** começou a seguir você") — single `<p>` with a `<strong>` or styled `<span>` for the name
  - **Timestamp**: label/14px/400, `rgba(214, 207, 193, 0.5)` — same `formatRelativeTime()` helper already implemented in `PostCard.jsx` ("agora" / "Xmin" / "Xh" / "Xd"). **Reuse this exact function — extract it to a shared util if not already, or duplicate verbatim; do not reinvent the format.**
  - **Inline actions row** (only for `type === 'follow_request'` AND `status` is not yet resolved): "Aceitar" button + "Rejeitar" button, horizontal, gap `--space-sm`. After resolution, this row is replaced by the status label (D-06)
- **Unread indicator**: 8px circle, `background: var(--color-accent)`, positioned at the leading edge of the card (left side, vertically centered, OR as a small dot adjacent to the timestamp — implementation detail; the contract requires it be visually distinct and immediately scannable per D-03). Read notifications render no dot (occupy the same layout space with `visibility: hidden` to prevent layout shift, OR simply omit — either is acceptable, prefer omit for simplicity).

Card states:
- **Unread**: background `rgba(140, 110, 79, 0.08)` (accent tint), unread dot visible
- **Read**: background transparent (dominant shows through), no dot — visually identical to a default `UserResultCard` row otherwise

Card border: `border-bottom: 1px solid rgba(214, 207, 193, 0.1)` (same separator as `PostCard`/`UserResultCard`)
Card background transition on read: instant (no fade animation — keep it simple, matches the rest of the app's lack of micro-animations)

**Inline Aceitar/Rejeitar buttons** (D-05):
- "Aceitar": filled button, `background: var(--color-accent)`, `color: var(--color-surface)`, no border — visually the strong/primary action (mirrors `btnPrimary` class from `FollowButton.module.css`)
- "Rejeitar": ghost-destructive button, `background: transparent`, `border: 1px solid var(--color-destructive)`, `color: var(--color-destructive)` — mirrors `btnConfirmDestructive` class from `FollowButton.module.css`
- Both buttons: `min-height: var(--touch-min)` (44px), `padding: var(--space-xs) var(--space-md)`, `border-radius: var(--radius-button)`, `font-size: var(--text-label)`, `font-weight: var(--weight-semibold)`
- Tapping either button: (a) calls the existing `PATCH /api/follows/:id/accept` or `/reject` endpoint, (b) marks the notification read (D-07 — same request or follow-up call, implementation detail), (c) replaces the button row with the resolved status label, (d) stops event propagation so the card's own tap-to-navigate handler does not also fire (mirrors the `e.stopPropagation()` pattern in `UserResultCard`'s `.followWrap`)
- Loading state: button shows `Spinner` (16px) in place of label, both buttons disabled during the in-flight request
- Error: `ErrorBanner` rendered below the action row (message: "Algo deu errado. Tente novamente." — verbatim reuse of `FollowButton` error copy)

## Interaction States

### Loading
- Page-level load: `Spinner` (28px) centered in content area, `aria-label="Carregando notificações..."`
- Pagination/infinite-scroll load (if applicable): `Spinner` (24px) centered below last card
- Inline action load (Aceitar/Rejeitar): `Spinner` (16px) replaces button label, both buttons `disabled`

### Error
- List load error: `ErrorBanner` at top of list, copy: "Erro ao carregar notificações. Tente novamente."
- Mark-read error (background, on tap-to-navigate): `ErrorBanner`, copy: "Não foi possível marcar como lida. Tente novamente." — **non-blocking**: navigation proceeds regardless (marking read is a side effect, not a gate; the user should never be prevented from viewing content because a read-receipt failed)
- Accept/Reject error: `ErrorBanner` below the action row, copy: "Algo deu errado. Tente novamente." (verbatim `FollowButton` reuse)

### Empty
- No notifications: centered empty state — heading "Nenhuma notificação ainda" (body/600) + body "Quando alguém interagir com você, vai aparecer aqui." (body/400, muted), `--space-2xl` vertical padding, no CTA (matches structure, not content, of Phase 4 feed empty state)

### Read/Unread visual states
- Unread: accent-tinted background (`rgba(140, 110, 79, 0.08)`) + 8px accent dot (D-03)
- Read: transparent background, no dot
- Transition: instant on tap (no animation)

### Focus / Accessibility
- All interactive elements: `outline: 2px solid var(--color-accent-alt); outline-offset: 2px` on `:focus-visible` (unchanged convention)
- Buttons: `cursor: pointer`; disabled: `opacity: 0.5; cursor: not-allowed`
- Avatar `alt` = actor's name
- Aceitar button: `aria-label="Aceitar solicitação de {Nome do ator}"`
- Rejeitar button: `aria-label="Rejeitar solicitação de {Nome do ator}"`
- Bell icon: `aria-label="Notificações"` (unchanged from Phase 4)
- Badge pill: visually `aria-hidden="true"` with an adjacent screen-reader-only span carrying "{count} notificações não lidas" (mirrors the `.sr-only` utility class already present in `AppShell.module.css`)
- Notification card: the whole card is a tap target; if implemented as a `<div onClick>`, it must carry `role="button"` + `tabIndex={0}` + `onKeyDown` (Enter/Space) for keyboard accessibility — OR implemented as a `<button>`/`<Link>` wrapper to get this for free (preferred — less code, matches CLAUDE.md "Simplicity First"; `UserResultCard` currently uses a `<div onClick>` without keyboard handling, which is a pre-existing gap — **do not silently fix it there**, but do not repeat the gap here if a simpler accessible pattern is available)
