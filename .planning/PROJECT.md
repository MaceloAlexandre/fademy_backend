# Fademy

## What This Is

Fademy is a mobile-first, invite-only mini social network for educational institutions — built first for the **Faculdade Católica da Paraíba** but multi-tenant from day one. Students, professors, staff, and coordinators join by invitation, build profiles, post content (text/images/links) tagged by category, follow each other, comment, get in-app notifications, and chat 1:1 or in groups. It ships as an Express/MongoDB REST API plus a React web frontend, and is intended to go to production on the owner's VPS.

## Core Value

A student opens Fademy on their phone, gets in via an invite, and immediately sees a personalized feed of posts from people they follow — and can post their own. The invite→register→post→feed loop is the heart; if that works flawlessly on mobile, Fademy feels real.

### Active

<!-- Current scope. Building toward these. Full spec is v1. -->

**Auth & Invites**
- [ ] Invite-only registration; invites generated by admin/coordenador/professor/funcionario, bound to the inviter's institution and carrying the new user's role
- [ ] Invite tokens expire (`expiresAt` checked on accept)
- [ ] Registration requires a mandatory profile photo
- [ ] JWT-based login/session; logout
- [ ] Role-based authorization enforced in middleware before controllers

**Profiles & Social Graph**
- [ ] Public vs private profiles (`isPrivate`)
- [ ] Follow public profiles directly; private profiles require accept (status `pending`→`accepted`)
- [ ] Block a user: bilateral follow removal; blocked users can't message, see posts, or appear in search
- [ ] User search (respecting blocks)

**Content**
- [ ] Create posts with text, images, and links (links only for permitted roles; `hasLink` validated by role in backend — 403 for `aluno`)
- [ ] Tag posts with categories (fixed: `content` type + `area` type)
- [ ] Comment on posts
- [ ] Personalized feed from accepted follows, filtering out blocked users both directions

**Notifications**
- [ ] In-app notifications stored in DB with `read` flag, polymorphic `refId`/`refModel`
- [ ] Dispatched via a notification service (never inline in controllers)
- [ ] Types: follow_request, follow_accepted, new_follower, post_comment, invite_received, message_received (post_like if likes implemented)

**Chat & Groups**
- [ ] 1:1 chat only between mutually-following users (real-time via Socket.io)
- [ ] Adding a third person turns a conversation into a group
- [ ] Groups can be public (searchable) or private
- [ ] Messages support text and media (images/files)

**Platform & Frontend**
- [ ] Multi-tenant: all data scoped by institution from day one
- [ ] Seed: Faculdade Católica da Paraíba institution, all fixed categories, a bootstrap admin
- [ ] Media uploads to S3
- [ ] React frontend, mobile-first, in sibling folder `MINIREDESOCIAL_FRONT`
- [ ] Deployable to VPS

## Constraints

- **Tech stack (backend)**: Node.js, Express, MongoDB, Mongoose, dotenv, JWT — fixed by the existing spec.
- **Tech stack (frontend)**: React, mobile-first — chosen by owner; native app is a later milestone.
- **Design**: Color palette dark blue, black, beige, tobacco brown — owner-specified brand for Fademy.
- **Real-time**: Socket.io for chat messages; polling for notifications — balances demo impact against the owner's real-time experience and the 3-week window.
- **Media**: Uploads to S3 (owner has a bucket).
- **Deployment**: VPS owned by the user.
- **Timeline**: ~3 weeks until institutional presentation — slice work as vertical MVP so there's always a deployable, demo-able product; highest-risk features (chat) land last.
- **Multi-tenancy**: institution scoping required from day one, even though only Católica PB seeds initially.
